# 经营支撑路由

| 约束 | 读取 |
|---|---|
| 增长可能导致缺现金、超负荷或低利润 | [现金流与容量](cashflow-capacity.md) |
| 要把本系统作为咨询/陪跑服务交付 | [咨询与服务交付](consulting-delivery.md) |
| 要把定制专业服务变成可重复报价 | [服务产品化](service-productization.md) |
| 消费品订单、库存、发货、退换与投诉失控 | [B2C履约](b2c-fulfillment.md) |
| 工作坊涉及权力、冲突或远程协作 | [高级共创主持](advanced-facilitation.md) |
| 涉及隐私、授权、版权、宣传或行业监管 | [合规治理](compliance-governance.md) |
| 需要证明项目或品牌营收系统是否有效 | [衡量与评估](measurement-evaluation.md) |
| 资料、版本、AI处理和单一事实源混乱 | [AI与知识运营](ai-knowledge-ops.md) |
| 要迁移到消费品、服务、IP、门店或B2B | [行业适配](industry-adaptation.md) |

支撑模块约束业务流程，但不替代相应领域的持证专业人员或专项执行团队。
