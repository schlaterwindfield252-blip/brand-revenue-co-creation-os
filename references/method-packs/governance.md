# 临时方法包治理

## 三层方法体系

- **核心层**：证据可追溯、价值兑现与商业可行性、真实用户证据能够影响决定、按风险校准门槛、最小可靠记录、用户授权和专业边界。参与次数、输出栏目、评分、生命周期顺序及模块数量均可按任务调整，不当成不可变原则。
- **正式扩展层**：经过真实项目复核、适用范围和失败条件清楚的方法；正式收录不等于普遍有效。
- **临时方法层**：新理论、书籍框架、行业打法或企业内部方法，仅对当前项目或实验有效。

## 状态

- `experimental`：正在验证；
- `project-only`：只为当前项目采用；
- `approved-extension`：已通过晋升标准；
- `retired`：证据不足、过期、冲突或风险不可接受。

## 准入

1. 记录来源、作者/机构、版本、日期和许可边界。
2. 说明它要改变哪个决定，而不是它听起来多新。
3. 映射适用阶段、客群、行业、输入、输出和前提。
4. 检查与核心原则、现有方法、合规和用户选择是否冲突。
5. 规定证据等级、已知限制、失败信号、复核日和停止条件。
6. 以最小实验运行，保留原始结果和意外后果。

## 操作顺序

1. 用 [方法包模板](method-pack-template.md) 记录方法边界。
2. 在 [方法登记表](registry.md) 或可复制的 [方法登记CSV](../../assets/integrated/method-registry.csv) 中创建稳定ID，初始状态为 `project-only` 或 `experimental`。
3. 将方法映射到一个品牌、营销或营收主模块；方法包不能独立替代核心流程。
4. 运行最小测试，在复核日决定继续、修改、晋升或淘汰。
5. 更新登记表、证据、冲突和适用边界。

## 晋升

方法只有在独立的适配项目或周期中改变了实际决定、产生可复核结果、实施负担可接受、未引发不可接受反指标，且适用边界清楚时，才可考虑正式扩展。预先按推广范围和错误代价规定观察对象与窗口，保留全部失败、未执行和不确定结果；不设通用的案例数量及格线。按 [验证协议](../integrated/validation-protocol.md) 保存记录。一次成功、模拟场景、专家名气或流行度不能替代真实验证。

## 版权与来源

保存结构化转述、决策规则和必要短引文，不复制受版权保护的整本书、课程或付费材料。需要当前事实或原文精确含义时，使用权威来源并注明日期。
