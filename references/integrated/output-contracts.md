# 输出契约

用户指定形式优先。只包含对当前决定有用的信息；以下是检查项，不是每次必须逐条输出的目录。

## 默认轻量决策

用自然语言交付：判断与依据、关键未知、下一动作及承受上限、复核结果与时机。已有确定负责人或日期就写明；建议安排标“建议”，未知标待定。不强制三引擎分栏、成熟度评分、利益相关者全图或资产清单。

若用户要的是一份文案、报价或分析表，直接完成该产物，并补影响使用的必要假设。一次性任务可以不建文件；持续跟进才用 [行动卡](../../assets/integrated/decision-action-card.md)。

## 需要时追加的细节

| 场景 | 应增加的判断依据或产物 |
|---|---|
| 诊断 | 关键反证、竞争解释、为什么这个动作能区分它们；阶段未知可明写未知 |
| 策略 | 对象与情境、资源选择、关键假设、验证与回退条件 |
| 工作坊 | 要作出的决定、必要参与者、决策权、时间安排、分歧和会后动作；八角色按需兼任 |
| 营销 | 客群、信息及证明、渠道/入口、承接与成本、主要指标及反指标 |
| 销售/报价 | 结果、范围/排除项、责任、成本与价格依据、证明、有效期和下一步；缺成本时可出假设草案，不能断言盈利 |
| 交付/增长 | 交接、首个价值、验收、异常和付款；增长路径按业务选择复购、推荐或后续需求等 |
| 高风险或扩量决定 | 明确证据窗口、经济/现金/容量约束、停止与回退条件 |
| 效果评估 | 基线、实际行动与成本、结果/失败/不确定、外部影响；见 [验证协议](validation-protocol.md) |

项目需要更多记录时，只创建实际使用的模板。维护记录消耗的时间也属于实施成本；删除未用于任何决定的字段。

## 证据不足时

说明能判断什么、不能判断什么；为低风险行动给出可撤回的下一步。门槛状态使用 [阶段门](lifecycle-gates.md) 的定义，不把“未观察到”自动解释为失败，不用文档完整度掩盖证据缺口。
