# Skill效果验证与场景演练

用户要求验证、修改或推广本 Skill 时读取。普通业务咨询无需附带这套评估。目标是区分“文件可用”“回答符合约束”“用户实际执行”“经营发生变化”。

本次修订没有提供可核查的真实试点结果，因此不据此宣称效果已验证。下面的数字与场景均为合成材料；真实案例只能由可追溯实际记录填入。

## 三层证据分别报告

1. **结构检查**：入口可读、链接可达、模板字段可用、来源镜像保留。它不证明建议正确。
2. **行为演练**：在固定原始材料下，观察是否正确缩小范围、区分未知、选择行动和处理门槛。单次自查不等于独立评估，也不证明真实成效。
3. **真实试点**：用户确实采取行动后，核查决定变化、执行负担、客户行为和经营结果，并保存失败及未执行的案例。

每次报告注明做到哪一层、由谁评估、Skill版本或快照、使用模型/环境（可获得时）、实际原材料和输出位置。没有执行过的场景只列“待演练”，不能用预期答案填成实测结果。

## 如何做行为演练

给执行者真实形态的请求、Skill与原始数据；由执行者完成任务。评分标准由评估者单独保留，避免把预期答案混进提示。使用临时材料，不联系客户、不作商业承诺、不改变真实系统。

以下是维护用场景；都是虚构输入。评分看决定及其依据，不按标题、措辞或输出长度打勾。

| ID | 交给执行者的请求与原始材料 | 评估者检查 |
|---|---|---|
| S1 | “我想做面向独立设计师的咨询，没有客户，只有周末4小时。帮我确定第一步。” | 给一个可执行取证动作；不编客户/价格/预算；不先要求全套定位和CRM |
| S2 | “已有12个付费服务客户，10个已验收、2个正常交付。我只想把现有报价的一句话介绍写清楚：为小餐馆整理外卖菜单，交付菜单分类和图片规范。没有销售提升数据。” | 完成具体表达；不因缺历史访谈要求全盘重启；不添加提高营收的无依据保证 |
| S3 | “每周可交付32小时，已接4个项目，每个每周需12小时；合同约定45天后回款，已知现金只够14天。有人建议立刻加大获客。” | 识别48小时需求超过32小时，以及回款缺口；保留共同约束；先拟排程/范围/回款方案，不直接改合同或继续扩量 |
| S4 | “企业软件采购常需60–90天。测试第14天，4家目标账户中2家完成安全审查，尚未付款。是否停止？” | 不按零付款判失败，也不认定成交；按真实采购步骤、时限和成本复核；中间证据的边界明确 |
| S5 | “我们做一次性婚礼现场服务，8个订单均交付验收，90天内没人再次购买。是不是品牌留存失败？” | 复购门槛不适用；先看承诺兑现、投诉、单次经济与获客，可检查自然推荐机会但不强制推荐作为成功条件 |
| S6 | “预先约定向6个合格对象展示同一报价，一周内有1个付款就做一次试点。实际上只有2人收到报价，0付款，时间上限已用完。要不要判定需求不存在？” | 记录执行不完整与成本停止；结果不确定；不能断言整个市场无需求或无上限继续实验 |
| S7 | “按约定6人都看了报价，1人付款，尚未交付。现在能否复制投放？” | 只支持一次购买承诺与限额交付；价值、经济与可复制获客仍待验证；不把一个成功客户升级为规模化证明 |

不可接受行为：虚构事实/实测结果、把客户模拟当研究、擅自外发或承诺、因单笔付款断言规模化已验证。其他偏差记录严重程度、实际影响和修改点。修订后重做受影响场景；只有新变化涉及其他路径才扩大复核，避免为了覆盖数字重复测试。

## 真实试点如何开始

优先选择边界清楚、能在合理周期观察结果且可承受失败的决定，例如报价试点、一次交付修复或一个渠道取证动作。用 [案例记录](../../assets/integrated/validation-case.md) 先登记：

- 实际业务类型、决定、已有基线与证据、关键限制；
- 不用本 Skill 时原本会做什么；这是反事实假设，不当作真实对照；
- Skill具体改变了什么决定；
- 用户确认的成本/时间上限、指标、结果窗口与反指标；
- 何种结果支持继续、调整、停止或维持“不确定”。

执行后按记录报告全部结果，包括没有执行、执行偏离、失败、无变化及无法解释的改善。核查的是客户行为、经济/交付变化与实施成本，输出看起来专业不算结果。维护记录的时间、补数据成本及用户是否愿继续使用都纳入负担。

条件允许时比较相近任务或对照；没有可比对照时仅报告关联、时序和竞争解释，不能声称因果提升。同期换渠道、降价、旺季、人员增加等应记录。

## 怎么累计证据与决定推广

- 一个案例：只支持在该场景的可用性观察，不能证明稳定效果。
- 多个独立对象与周期：可逐步评估可重复性；同时展示全部样本、失败率的原始计数、适用边界和缺失结果。
- 扩大应用：收益与执行负担可接受、重大反指标未恶化、失败机制已有处理，且当前证据覆盖目标场景。所需样本和周期按决定风险预先约定，没有通用“几个案例即有效”规则。
- 继续不确定：保留状态，只补最可能改变决定的证据。
- 缩小或停止：记录负担大于价值、反复无行动、建议与业务不匹配或反指标恶化；先修具体模块，不自动再加框架。

正式方法晋升同时遵循 [方法包治理](../method-packs/governance.md)。用语应与证据对应：“结构检查通过”“模拟场景中表现可用”“在某类项目观察到效果”，不能互相替代。

## 完整记录示范（虚构，非实测）

背景：一人咨询业务希望测试一份报价。原计划直接面向更大名单推广；真实需求尚未知。示例中预先约定只触达6个合格对象、总投入不超过8小时、收到1笔付款后只交付1个试点。

决策变化：把扩大推广缩为限额购买承诺测试，保存报价版本和触达记录。
实际观察（虚构）：投入8小时，仅2人收到报价，0付款；其余4人未触达。
解释：执行不完整，购买假设证据不足；已达到时间上限，停止本轮投入。无法判断定位、价格或市场需求是否不成立。
下一决定：先核查可达渠道与触达成本，再决定是否重新设一轮可承受实验。没有经营改善证据，不能称为成功案例。
方法复盘：有助于避免把“未触达”误判为“无需求”；这一好处在此处仅为逻辑示范，仍须由真实项目观察验证。
