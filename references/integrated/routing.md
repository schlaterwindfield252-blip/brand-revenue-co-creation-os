# 统一路由

## 先判断本次决定的范围

| 请求 | 使用方式 |
|---|---|
| 单一品牌或营收问题 | 优先对应独立 Skill；明确调用本 Skill 则进入相应镜像模块 |
| 比较一个报价、分析一段客户反馈、改一个具体产物 | 轻量决策；只交付本次判断或产物 |
| 品牌、营销、销售、交付之间相互影响 | 选择直接影响决定的主模块，再加确有必要的辅助模块 |
| 不知道问题在哪里 | 先看最近事件、当前损失与资源限制；仍不清楚才做相关维度的成熟度诊断 |
| 要评估本方法或系统是否有效 | [验证协议](validation-protocol.md)；不要把材料覆盖当效果 |

## 识别约束，不把顺序当根因

先确定业务类型、所讨论的报价/客群及决定的风险。用 [阶段门](lifecycle-gates.md) 找出支持与缺口，但前序记录缺失不等于实际阶段未完成。已购、使用、验收等真实事件可以支持阶段判断；只补影响当前选择的证据。

比较候选约束：当前造成的损失、是否阻断下一动作、判断依据、取证成本及能否回退。默认选一个当前处理重点；例如“回款晚 + 创始人容量已满”可能必须共同处理，允许必要的两个模块并行。

紧急的现金、交付或客户伤害问题优先于重新定位和完整访谈。证据不足时保留竞争解释，选择能区分它们的动作，不用成熟度低分证明因果。

## 按约束选模块

| 可观察现象 | 候选主模块 | 先检查的其他解释 |
|---|---|---|
| 没有客户问题的直接证据 | 客户验证 | 接触不到用户、样本偏差 |
| 价值说不清或同质化 | 品牌诊断/价值识别 | 产品体验无差异、客群选错 |
| 多方目标冲突 | 利益相关者共创 | 决策权或激励未明确 |
| 产品、传播与运营脱节 | 品牌系统 | 交付能力、承诺过度 |
| 没有足够合格接触 | GTM/渠道 | 触发频率低、客群边界不清 |
| 有流量但无有效线索 | 信息与承接 | 流量来源不匹配、路径故障 |
| 有线索但无法成交 | 报价/销售CRM | 错误买家、采购时间、产品不合适 |
| 成交后交付失控 | 交付与客户成功 | 范围、容量、客户依赖 |
| 消费品缺货、错发、破损、退货 | B2C履约 | 供应批次、夸大承诺 |
| 定制服务负担增加 | 服务产品化 | 定价低、返工、销售承诺失控 |
| 满意但没有复购 | 生命周期/价值证明 | 购买周期未到、一次性需求、目标本就不需复购 |
| 增长导致现金或时间不足 | 现金与容量 | 付款条件、单位经济、在制数量 |
| 会议多而无决定 | 高级主持 | 缺少决策权、没有足够事实 |
| 用户要求采用新方法 | 方法包 + 业务模块 | 原问题不需要额外方法 |

这些是候选解释，不是从现象直接推导根因的规则。

## 控制负担

先用现有材料回答：要决定什么、最近发生什么、承受上限是什么。不要把所有未知转成问卷。每次动作只增加会影响判断的字段；已有记录可用就不新建。

共创角色可以由一人兼任；只有存在跨方决策问题时才组织工作坊。需要校准门槛时读 [门槛校准](decision-calibration.md)，业务不匹配时读 [业务适配](../extensions/industry-adaptation.md)。
